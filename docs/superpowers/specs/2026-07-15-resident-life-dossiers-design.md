# 灯塔镇居民人生档案设计

## 目标

点击任意 AI 居民即可看到一个持续更新的人生档案，而不只是人物简介和上一段对话。档案要让观察者快速理解这个人是谁、最近过得怎样、与谁亲近或恋爱、靠什么谋生，以及当下正在做什么。

## 采用方案

采用“固定人生底稿 + 实时世界状态 + 对话记录推导”的混合方案。

- 固定底稿保存成年年龄、职业、住处、饮食、衣着、性格标签、长期目标和关系性质。
- 实时状态读取 Convex 世界中的移动、活动和交谈，计算心情、精力、健康、财务与声望的当前显示值。
- 近期动态读取本地消息记录和当前活动，形成时间线；不额外调用大模型，因此不会增加 Ollama 负载。
- 关系网明确区分友情、心动、恋爱和商业。关系描述只表达角色设定与已经发生的互动，不把普通交谈自动误判为恋爱。

这种方案比纯静态卡片更像真实生活，又比每次点开都调用大模型更稳定、更省本机算力。

## 界面

居民详情从上到下分为：

1. 真人影像画廊：头像、工作、生活、社交四张照片，标注“AI 生成角色影像”。
2. 近况总览：当前活动、心情、精力、健康、财务、声望六项。
3. 人生资料：成年年龄、职业、住处、今日穿着、饮食偏好、当前目标。
4. 社会关系：用不同颜色区分好友、心动、恋爱与商业关系，显示亲密度和一句关系说明。
5. 最近发生：当前行动和最近参与的本地对话摘要。
6. 原有人物设定、进入交谈按钮及历史对话，保持功能不丢失。

## 真人影像规范

每位居民生成一张同身份四宫格摄影联络表，再无损切成四张站点照片，以确保同一居民四张图面貌一致。整体为电影感写实摄影，场景统一在架空江南水乡灯塔镇，服装体现职业与性格；不出现现代品牌、文字、水印、现实名人或未成年人。所有角色均为明确成年人。

## 数据与边界

- 角色底稿位于 `data/worlds/lighthouse-town/lives.ts`，以角色 ID 为稳定键。
- `convex/lives.ts` 将底稿与世界、消息数据组合为 `residentDossier` 查询结果。
- `ResidentDossier.tsx` 只负责展示，`PlayerDetails.tsx` 继续处理聊天交互。
- 照片位于 `public/assets/worlds/lighthouse-town/residents/<角色ID>/`。
- 没有照片或历史消息时显示清晰的降级状态，不阻塞聊天。

## 验证

- 单元测试覆盖九人资料完整性、全员成年、照片数量、关系类型和档案推导。
- TypeScript 构建与世界资产校验必须通过。
- 迁移后浏览器检查九名居民、玄微先生、档案画廊、关系卡和对话入口。
- 原八人活动记录、消息记录和世界 ID 不重置。
