# 灯塔镇中文化改造设计

## 目标

基于 `a16z-infra/ai-town` 当前 `main` 分支构建一个可运行的中英双语版本。保留 Convex 模拟引擎、多人交互和 PixiJS 渲染能力，将默认世界改造为架空江南水乡「灯塔镇」，并重写界面文案、角色、故事、对话提示词、地图和人物视觉资产。

首版同时支持标准 npm + Convex Cloud 流程和 Docker 自托管 Convex。模型配置仅由服务端环境变量控制，不把密钥暴露给浏览器。

## 非目标

- 不把项目扩展成任意数量世界包的可视化编辑平台。
- 不实现浏览器端模型密钥管理。
- 不重构 Convex 游戏循环、寻路、对话存储或多人同步机制。
- 不承诺任意模型厂商的私有协议；非内置厂商通过 OpenAI-compatible 接口接入。

## 总体架构

采用模块化「灯塔镇世界包」，外围增加语言层和模型配置层，核心模拟引擎保持不变。

1. `src/i18n/` 保存 `zh-CN`、`en` 词典、语言类型、插值函数和 React 上下文。界面默认简体中文，语言选择保存到 `localStorage`，页面 `lang` 属性和日期格式随之切换。
2. `data/worlds/lighthouse-town/` 保存世界清单、双语角色资料、角色行为目标、地图模块和精灵表元数据。`data/characters.ts` 作为兼容入口重新导出默认世界数据，减少对上游调用点的侵入。
3. `public/assets/worlds/lighthouse-town/` 保存灯塔镇地图瓦片、装饰物、动画和人物精灵资源。默认地图为江南水乡，中央灯塔是视觉和故事地标。
4. `convex/util/llm.ts` 改为基于环境变量解析的提供商配置。内置 Ollama、OpenAI、Together.ai，并保留通用 OpenAI-compatible 端点。
5. `convex/aiTown/` 中的代理提示词通过统一世界设定和语言约束组装，避免各处散落硬编码英文提示。

## 双语规则

- UI 可由每个浏览器独立切换中英文，包括标题、帮助、按钮、状态、Toast、输入提示、无障碍标签和日期格式。
- 角色名称、简介和静态世界介绍提供中英两套内容。
- 模拟对话是共享全局状态，不能安全地为不同观察者同时显示不同语言版本。因此部署级 `WORLD_LOCALE` 决定代理对话语言，默认 `zh-CN`；浏览器语言切换只影响界面和静态资料。
- 当 `WORLD_LOCALE=en` 时，使用英文角色资料和英文提示词；`zh-CN` 时要求角色自然使用简体中文，避免翻译腔和无意义中英混杂。
- 未找到翻译键时回退英文，并在开发环境输出缺失键警告。

## 世界与角色内容

灯塔镇是架空东方水乡。青瓦白墙、石桥、水巷、茶馆、工坊和书院构成日常空间，镇中心的古老灯塔在没有海的水乡中持续发光。居民日常生活是主线，灯塔来历、周期性雾潮和失落航路作为慢速暗线。

首版沿用上游五个活跃代理槽位并全部重写：

- 林澜：灯塔守望人，温和谨慎，记录异常灯光。
- 沈砚：书院先生，博闻克制，研究镇志中的缺页。
- 唐果：茶馆主人，热情健谈，是镇上消息中心。
- 墨七：摆渡人，寡言可靠，声称在雾中见过不存在的航道。
- 苏萤：机关匠，聪明好奇，尝试修复灯塔内部装置。

每名角色包含双语姓名、公开简介、私有身份、长期目标、说话风格、关系钩子和灯塔暗线线索。角色不得以系统提示、语言模型或游戏 NPC 自称；内容保持全年龄、非歧视和非操控性。

## 视觉与地图

- 维持上游 32×32 像素角色规格和 PixiJS 动画接口，重新制作八个角色槽位及玩家形象，保证四方向行走帧尺寸一致。
- 新地图保留上游碰撞与寻路所需的背景层、物体层和动画精灵结构，替换为灯塔镇瓦片集。
- 地标包含中央灯塔、石拱桥、茶馆、书院、机关工坊、码头、荷塘和住宅巷道；可行走区域形成闭环，避免代理被封闭装饰困住。
- UI 保持像素游戏语言，替换为黛青、米白、朱砂和暖灯黄配色，并加入适合中文显示的像素字体回退。英文显示仍保持清晰。
- 所有新增视觉资产使用项目内可再分发的原创资产，并记录生成或制作说明；不覆盖上游许可证和署名。

## 模型接入

环境变量以 `LLM_PROVIDER` 为显式选择，支持 `ollama`、`openai`、`together`、`custom`。每个配置包含 API 地址、聊天模型、嵌入模型、嵌入维度、API 密钥和停止词。

- Ollama 使用 `OLLAMA_HOST`、`OLLAMA_MODEL`、`OLLAMA_EMBEDDING_MODEL`、`OLLAMA_EMBEDDING_DIMENSION`。
- OpenAI 使用 `OPENAI_API_KEY`、`OPENAI_CHAT_MODEL`、`OPENAI_EMBEDDING_MODEL`、`OPENAI_EMBEDDING_DIMENSION`。
- Together.ai 使用现有同名变量和可配置维度。
- 其他厂商使用 `LLM_API_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_EMBEDDING_MODEL`、`LLM_EMBEDDING_DIMENSION`。

启动时验证必需变量和正整数嵌入维度，错误信息同时提供中文说明和变量名。更换嵌入模型或维度后必须清空旧向量数据，中文文档明确标注这一破坏性操作，但不自动执行。

## 数据流

浏览器语言选择进入 i18n 上下文，组件只通过翻译键渲染静态文案。Convex 初始化从默认世界包导入地图和角色。代理生成对话时，提示组装器读取部署级世界语言、世界背景、角色身份、记忆和当前对话，再调用统一模型配置。模型输出仍走上游消息与记忆存储流程，不改变数据库结构。

## 错误处理

- 翻译缺失：英文回退，开发环境警告，生产环境不中断。
- 不支持的语言：回退 `zh-CN`。
- 模型配置缺失或冲突：初始化前快速失败，不记录 API 密钥。
- 模型端点失败：保留上游指数退避；错误仅包含状态码和经过截断、脱敏的响应摘要。
- 视觉资源加载失败：PixiJS 显示可识别的占位纹理并输出资源路径，避免黑屏。
- 地图或精灵元数据无效：构建或测试阶段失败，不把错误推迟到运行时。

## 测试与验收

自动化验证包括：

- i18n：中英翻译键集合一致、插值正确、缺失键回退、语言持久化。
- 模型配置：四类提供商解析、默认值、缺失变量、无效维度和密钥脱敏。
- 内容：角色双语字段齐全、角色槽位与精灵引用存在、提示词按世界语言组装。
- 地图与精灵：文件存在、尺寸满足瓦片/帧约束、地图数组长度与宽高一致、出生点和主要地点可达。
- 回归：上游 Jest 测试、TypeScript 构建、ESLint。
- 运行：Convex Cloud 流程完成前端构建和配置检查；Docker Compose 完成配置解析与服务启动检查。在没有用户账号或模型密钥时，不声称完成真实云端对话测试。
- 浏览器冒烟：简中默认页可加载、切换英文后主要界面更新、选择角色和聊天面板可打开、移动端不出现关键控件遮挡。

完成标准是：全新安装可按中文 README 启动；默认看到灯塔镇中文界面与新视觉；五名代理使用中文设定和提示；中英 UI 可切换；四类模型配置有测试覆盖；构建、Lint 和测试通过。

## 迁移与兼容

上游角色与地图数据只在首次初始化时写入 Convex。已运行旧世界的部署必须先导出需要保留的数据，再显式执行清库和重新初始化。文档给出命令和风险提示，不在安装脚本中自动清库。保留 MIT 许可证、上游署名和原仓库链接，并在 README 中说明本项目为中文化衍生版本。
