# 灯塔镇论文级社会观察日报设计

日期：2026-07-16  
状态：已完成产品设计，等待用户审阅后进入实施计划

## 1. 目标

把现有“灯塔镇观察者日报”从运营摘要升级为可用于社会学量化分析、人类学田野记录和可复现实验的数据产品。研究者应能像全知观察者一样回看全镇，但报告必须严格区分：

1. **可观察事实**：系统真实记录的动作、位置、对话、交易、关系事件和公共事件。
2. **统计指标**：由公开计算规则从事实层得出的计数、比例、网络和变化值。
3. **解释性推断**：模型或规则给出的社会解释，必须附证据编号、置信度和方法来源。

主报告必须独立完整，不能要求读者另开 CSV 或 JSON 才能理解结论。结构化附件用于复核、统计和后续论文分析。

## 2. 研究范围与时间口径

- 观察对象：灯塔镇全部居民、机构、地点、对话和公共事件，包括观察者本人参与造成的影响。
- 日界线：`Asia/Shanghai` 自然日，00:00:00 至 23:59:59.999。
- 历史不可变：日报封存后，后续生活不能改写当日事实；若重新分析，只生成新版本并保留旧版本。
- 当前日允许生成“截至当前时刻”的临时报告，标题和元数据必须明确标注“未封存”。
- 观察者行为单列，避免把研究者介入误判为居民自发行为。
- 当前版本不宣称角色拥有真实人类意识，也不把模型输出直接等同于真实社会事实。

## 3. 总体架构

### 3.1 原始事件层

新增不可变的 `researchEvents` 记录。每条事件包含：

- 全局证据编号；
- 世界、自然日、发生时间与写入时间；
- 事件类型；
- 主体居民、其他参与者、地点和机构；
- 原始文本或结构化载荷；
- 来源模块与来源记录 ID；
- 是否由观察者介入；
- 数据质量标志。

首批事件类型：

- `activity_started`、`activity_completed`；
- `movement_started`、`place_arrived`、`place_departed`；
- `conversation_started`、`message_sent`、`conversation_ended`；
- `relationship_signal`、`relationship_changed`；
- `work`、`trade`、`consumption`、`service_used`；
- `goal_progress`、`mood_signal`、`conflict`、`cooperation`；
- `public_event`、`competition_result`、`observer_intervention`。

记录使用应用层幂等键，避免重试产生重复证据。原始对话保持原文，展示时另生成清洗版本。

### 3.2 每日事实快照层

`dailyResearchSnapshots` 保存每天的稳定统计输入：居民名单、职业和目标、关系边、机构定义、事件 ID 范围、对话 ID 范围、模型及代码版本。封存动作只引用已存在的原始事件，不复制或改写证据。

### 3.3 分析层

分析器使用纯函数先生成确定性指标，再把指标与受限证据交给本地模型生成解释。模型分析不得创造未记录的事件。

分析结果包含：

- 结论文本；
- 证据编号列表；
- 置信度：高、中、低；
- 分析类型：规则计算、本地模型归纳或研究者备注；
- 反例或不确定性说明。

### 3.4 报告版本层

`dailyResearchReports` 保存日期、版本、生成时间、封存状态、数据范围、模型信息、Markdown 正文、指标 JSON、证据索引和内容哈希。同一天可存在多个临时版本，但只能有一个当前封存版本；重新分析产生递增版本。

## 4. 主报告内容

导出的 Markdown 主报告按以下顺序完整呈现，不把核心分析外包给附件。

### 4.1 研究元数据

- 世界名称、报告日期、观察区间、生成与封存时间；
- 居民数量、事件数量、对话数量和数据完整度；
- 本地模型名称、提示词版本、代码提交和报告版本；
- 观察者介入次数。

### 4.2 当日社会全景

- 一页式核心结论；
- 当日最显著的社会变化；
- 活跃度、交往密度、机构使用和异常事件；
- 每项结论附证据编号或指标编号。

### 4.3 居民逐人纵向档案

每位居民均包含：

- 身份、职业、住处、人格和当前目标；
- 分时活动时间线与地点；
- 工作、消费、服务使用和目标推进；
- 交往对象、主动发起率、被邀请次数和独处时间；
- 情绪、精力、健康、经济、声望和社交属性的期初、期末及变化；
- 友情、恋爱、商业和冲突关系变化；
- 代表性言论与证据；
- 系统解释、置信度和替代解释。

### 4.4 社会关系网络

- 全部关系边表直接嵌入报告；
- 关系类型、强度、互惠性和当日变化；
- 度中心性、中介中心性、网络密度和互惠率；
- 小团体、桥梁人物、孤立风险及跨职业交往；
- 恋爱、友情、商业和冲突网络分别分析，不能混为单一“亲密度”。

网络结论必须说明小样本限制，9 人网络不得使用夸大的总体推断。

### 4.5 经济与制度生活

- 居民的生产、劳动、交易、消费和服务使用；
- 机构客流、服务类型、居民依赖度和跨机构协作；
- 商业伙伴、订单与资源流向；
- 若当前系统没有真实金额，报告只能称“交易/服务事件”，不得伪造收入和价格；
- 镇公所、书院、药庐、茶庄、食肆、集市、码头、机关坊和卦馆的实际社会作用。

### 4.6 空间社会学

- 每位居民访问地点、抵达时间、停留估计和移动路径；
- 地点访问量、独立访客、共现次数和时段热点；
- 相遇机会、空间集中度、职业空间分工和潜在空间隔离；
- 地图坐标只作为证据，报告使用机构名称解释社会意义。

### 4.7 对话、议题与传播

- 当日所有对话索引和重要对话摘要；
- 对话双方、开始结束时间、消息数和观察者是否介入；
- 议题首次出现、传播路径、重复提及和观点变化；
- 代表性原文节选，附消息证据编号；
- 区分角色明确陈述、行为暗示和模型推断；
- 不以关键词命中直接证明动机或情感。

### 4.8 人类学田野记录

- 饮食、服饰、职业习惯、地方语言和作息；
- 节气、玄学、仪式、竞赛、公共公告和地方规范；
- 典型互动场景的厚描；
- 日常生活连续性与非日常事件造成的中断；
- 研究者反身性备注：观察者介入如何改变现场。

### 4.9 合作、冲突与风险

- 合作、帮助、争执、回避和关系修复；
- 秘密、传言、异常与风险信号；
- 每项风险区分事实、可能解释和未知信息；
- 不把虚构悬疑自动诊断为心理或社会病理。

### 4.10 公共事件的后续影响

- 比赛、颁奖及其他公共事件的过程和结果；
- 事件前后居民活动、关系和对话主题变化；
- 获胜者与其他居民回归日常生活的证据；
- 仅在样本足够时讨论影响，不用单日相关性声称因果关系。

### 4.11 综合解释与研究命题

- 当日可支持的社会学命题；
- 支持证据、反例、置信度和下一日观察建议；
- 可供论文继续验证的假设，但明确标记为“待验证命题”；
- 与前一日报比较时列出变化，而非重写历史。

### 4.12 方法、局限与伦理说明

- 数据采集范围、遗漏和失败事件；
- 角色由大模型驱动造成的生成偏差；
- 本地 Gemma 模型、温度、提示词和版本；
- 小样本、模拟社会和观察者效应；
- 报告适合研究模拟系统，不可直接外推真实人群；
- AI 图片为虚构成年角色形象。

### 4.13 报告内附录

报告正文末尾直接附：

- 居民日表；
- 全量关系边表；
- 地点访问与机构使用表；
- 对话及议题索引；
- 原始证据索引；
- 指标定义和计算口径。

## 5. 指标口径

首版只计算可由当前系统可靠支持的指标：

- 活动数、完成数与按类别分布；
- 对话次数、消息数、主动发起数、交往对象数；
- 地点访问数、独立访客数、共现数；
- 关系边数量、类型、强度、变化和基本网络指标；
- 工作、交易、消费和服务事件数；
- 议题出现次数、参与者和首次传播顺序；
- 观察者介入次数及其后的短期互动变化。

停留时间只有明确到达与离开事件成对时才计算；缺失离开事件则标记为右删失。情绪只使用系统属性或明确语言信号，不进行临床推断。因果结论不在单日日报中自动生成。

## 6. 导出格式

观察台提供两种操作：

1. **预览研究报告**：在站点内阅读完整报告、折叠附录并点击证据回到对话或活动。
2. **导出研究档案包**：下载一个 ZIP，包含：
   - `灯塔镇社会观察日报-YYYY-MM-DD-vN.md`；
   - `居民日表.csv`；
   - `关系网络.csv`；
   - `地点访问.csv`；
   - `对话与议题.csv`；
   - `原始证据.json`；
   - `研究方法与局限.md`；
   - `manifest.json`，记录文件哈希和版本。

主 Markdown 内含全部核心内容和表格，附件仅用于机器分析与复核。

## 7. 生成流程

1. 用户选择日期并点击生成。
2. 后端按上海时区确定数据窗口，读取原始事件并校验完整性。
3. 纯函数生成居民、关系、空间、经济和议题指标。
4. 本地 Gemma 12B 对受限材料做分节归纳；失败时仍输出完整事实与统计报告，只把解释部分标记为未生成。
5. 证据校验器拒绝没有证据编号的具体事实性结论。
6. 保存带版本的报告，前端展示预览。
7. 导出器在浏览器或本地服务中生成 Markdown、CSV、JSON 和 ZIP。

## 8. 错误处理与数据质量

- 数据窗口不完整：报告顶部显示醒目的完整度警告。
- 模型超时：保留事实和统计章节，解释章节显示失败原因，不阻断导出。
- 重复事件：通过幂等键去重，并在方法附录记录去重数量。
- 缺少地点：保留坐标并标记“未命名地点”。
- 缺少关系基线：不计算变化，只呈现当日关系信号。
- 下载失败：保留已生成报告，可再次导出而不重复分析。
- 所有错误不删除原始证据。

## 9. UI 设计

观察台顶部的“导出日报”升级为“社会研究报告”。点击后打开研究面板：

- 日期选择和临时/封存状态；
- 数据完整度、事件数、对话数、模型与版本；
- “生成/重新分析”“预览”“导出档案包”按钮；
- 报告目录和分节阅读；
- 证据编号可展开查看原始活动或对话；
- 事实、指标、推断使用不同视觉标签；
- 长报告采用虚拟滚动或分节渲染，避免拖慢地图与居民模拟。

## 10. 测试策略

### 单元测试

- 上海时区自然日边界；
- 事件幂等和证据编号稳定性；
- 居民、关系、空间、经济和议题指标；
- 不完整停留事件和数据缺失；
- Markdown 表格、CSV 转义、JSON 清单和内容哈希；
- 每项推断必须引用有效证据。

### 集成测试

- 一组活动、移动、对话和交易能形成完整日报；
- 观察者介入被单列；
- 模型不可用时仍能生成事实报告；
- 同日重新分析产生新版本且旧版本不变；
- 封存报告不可被后续事件改写。

### 浏览器验收

- 能选择日期、生成、预览并导出档案包；
- 主报告包含全部 13 个章节及内嵌附录；
- 证据链接可定位到原始记录；
- 地图、观察台和居民运行不因报告生成而中断；
- 浏览器无关键错误，下载文件可重新解析。

## 11. 验收标准

1. 任意有数据的自然日可生成一份独立可读的论文级主报告。
2. 主报告包含量化社会学、质性田野、个体发展、关系、经济、空间、对话、文化、风险、公共事件、方法与全部附录。
3. 所有具体事实可追溯到有效证据编号；所有解释明确标注置信度和来源。
4. 可导出 Markdown、CSV、JSON 和带清单的 ZIP 研究档案包。
5. 模型失败不会丢失事实报告，历史封存报告不可变。
6. 全量自动测试、构建、资产校验、站点健康检查和浏览器实测通过后才能提交实现。

## 12. 非目标

- 不把 9 个模拟居民的结果直接外推到真实社会。
- 不自动代写完整论文或伪造参考文献。
- 不在没有真实交易金额时生成虚构财务报表。
- 不把角色语言自动当作真实心理诊断。
- 首版不实现跨多个小镇的大样本比较；数据结构保留未来扩展能力。
