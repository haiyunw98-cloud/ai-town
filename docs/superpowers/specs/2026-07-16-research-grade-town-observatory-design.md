# 灯塔镇论文素材级全景观察档案设计

日期：2026-07-16  
状态：根据用户反馈修订，等待审阅后进入实施计划

## 1. 目标

把现有“灯塔镇观察者日报”升级为一份完整、客观、可追溯的社会运行档案，为用户日后自行写论文保存材料。

系统的职责只有四项：

1. **完整记录**：保存居民的活动、移动、地点、机构使用、关系、交易、对话和公共事件。
2. **分类整理**：按日期、居民、地点、关系类型和事件类型归档。
3. **描述性汇总**：提供次数、时间、参与者和发生顺序等事实性统计。
4. **证据追溯**：报告中的每条记录都能回到原始事件或原始对话。

系统不替用户研究，不生成因果结论、社会学命题、心理诊断、人物动机或价值判断。报告是论文素材，不是论文结论。

## 2. 记录原则

- 记录对象：灯塔镇全部居民、机构、地点、对话、公共事件及观察者本人造成的介入。
- 日界线：`Asia/Shanghai` 自然日，00:00:00 至 23:59:59.999。
- 历史不可变：已经封存的某日档案不能被后续生活改写。
- 原文优先：对话原文、活动原文和原始时间必须保留，摘要不能替代原文。
- 事实与缺失分开：没有记录到的事情写“无记录”，不能由模型补齐。
- 观察者介入单列：用户进入世界、主动交谈或移动造成的变化必须标明。
- 模拟性质明确：这些材料描述的是由大模型驱动的虚构社会，不直接代表真实人群。

## 3. 数据架构

### 3.1 不可变观察事件

新增 `observationEvents` 表，每条事实写成一个不可变事件：

- 全局证据编号；
- 世界 ID、自然日、发生时间和写入时间；
- 事件类型；
- 主体居民、其他参与者；
- 地点、机构和坐标；
- 原始文本与结构化数据；
- 来源模块和原始记录 ID；
- 是否由观察者介入；
- 数据完整度标记；
- 幂等键，避免服务重试产生重复记录。

首批记录类型：

- `activity_started`、`activity_completed`；
- `movement_started`、`place_arrived`、`place_departed`；
- `conversation_started`、`message_sent`、`conversation_ended`；
- `relationship_signal`、`relationship_changed`；
- `work`、`trade`、`consumption`、`service_used`；
- `goal_progress`、`attribute_changed`；
- `conflict`、`cooperation`；
- `public_event`、`competition_result`；
- `observer_intervention`。

### 3.2 每日封存快照

`dailyObservationSnapshots` 保存某个自然日的事实边界：

- 当日居民、职业、住处和目标；
- 期初与期末生活属性；
- 期初与期末关系边；
- 机构与地点定义；
- 当日观察事件 ID；
- 当日对话和消息 ID；
- 赛事及公共事件 ID；
- 数据缺失和服务中断区间；
- 代码版本、模型名称和配置版本。

当前日可以生成“截至当前时刻”的临时快照。午夜后自动封存，封存快照不可修改；补录只能产生新版本并保留旧版本。

### 3.3 档案版本

`dailyObservationReports` 保存：

- 日期、版本、生成时间和封存状态；
- 数据时间范围与完整度；
- Markdown 主报告；
- 表格数据和证据索引；
- 文件内容哈希；
- 使用的代码提交与模型配置。

## 4. 主报告内容

主 Markdown 报告必须包含以下全部内容，读者不打开附件也能完整了解当天发生的事情。

### 4.1 档案元数据

- 世界、日期、观察起止时间；
- 生成时间、封存时间和档案版本；
- 居民数、事件数、消息数、对话数和地点访问数；
- 数据完整度与中断时间；
- 本地模型名称、代码版本；
- 观察者介入次数。

### 4.2 当日全镇概览

只做事实性概览：

- 当日有哪些居民活动；
- 有多少次活动、移动、对话、地点访问和机构服务；
- 有哪些交易、合作、冲突、关系变化和公共事件；
- 当日开始与结束时，全镇分别处于什么状态；
- 重要记录对应的证据编号。

不得在本节解释事件为什么发生，也不得推测长期影响。

### 4.3 全镇分时时间线

按时间顺序列出当天全部重要事件：

- 时间；
- 居民与其他参与者；
- 地点和机构；
- 事件类型；
- 事实描述；
- 证据编号。

报告提供完整时间线和按小时汇总。大量重复的低价值移动可以折叠，但不能删除，折叠记录仍出现在附录索引中。

### 4.4 居民逐人日档案

每位居民固定包含：

- 姓名、年龄、职业、住处、人格设定、穿着、饮食、生计和当前目标；
- 当日从第一条到最后一条的个人时间线；
- 去过的地点、抵达和离开时间；
- 做过的工作、交易、消费和服务使用；
- 与谁交谈、由谁发起、消息数量；
- 友情、恋爱、商业和冲突关系的期初、期末及明确变化事件；
- 情绪、精力、健康、经济、声望和社交属性的期初、期末值；
- 目标推进事件；
- 当日代表性原话；
- 与前一日相比发生了哪些可直接计算的变化。

若某项没有真实事件，显示“当日无记录”，不能用设定文本伪装成实际发生。

### 4.5 关系记录

关系必须按友情、恋爱、商业、冲突分别列出，报告包含：

- 当日期初关系表；
- 当日全部关系信号和明确关系变化；
- 当日期末关系表；
- 关系双方、类型、强度、标签和更新时间；
- 支撑变化的对话或事件证据。

系统可以记录交谈次数和共同活动次数，但不得据此自动判断“关系更好”“产生爱意”或“形成派系”。除非游戏状态明确写入关系变化，否则只称为“关系信号”。

### 4.6 经济、劳动与机构使用

报告逐条记录：

- 工作和生产事件；
- 商业合作、交易、消费和服务使用；
- 发生时间、双方、地点、项目和已记录金额；
- 每个机构的来访居民、服务类型和使用次数；
- 居民的收入、支出或库存变化，仅在系统有真实数值时展示；
- 九个机构当天是否实际被使用。

如果当前系统没有真实价格或金额，只记录“发生了交易/服务”，不生成虚构财务数据。

### 4.7 地点、移动与停留

- 每位居民完整行程；
- 出发地点、目的地点、出发和抵达时间；
- 有明确到达与离开记录时计算停留时长；
- 各机构访问次数和独立访客数；
- 同一时间、同一地点出现过哪些居民；
- 未命名坐标和路径失败记录。

没有离开事件的停留标记为“尚未结束”，不能估算虚假时长。

### 4.8 对话与议题档案

主报告包含：

- 当日每一组对话的参与者、开始结束时间和消息数；
- 谁发起、谁离开、观察者是否介入；
- 事实性对话摘要；
- 按出现顺序列出的主要话题词；
- 代表性原文节选与消息证据编号；
- 完整原始消息索引；
- 同一词或明确话题被不同居民提及的时间顺序。

话题传播只描述“谁在何时提到什么”，不自动推断影响关系或传播因果。摘要不得添加原文没有的事实。

### 4.9 日常文化记录

把实际出现的内容按事实归档：

- 饮食、服饰、职业习惯和作息；
- 节气、玄学、仪式、比赛、公告和地方规矩；
- 茶庄、食肆、书院、药庐、码头、集市、镇公所、工坊和卦馆中的日常场景；
- 角色实际说出的地方知识和民俗表述；
- 对应的活动或对话证据。

角色设定和当日实际表现分开呈现，不能把预设背景写成当天发生的事实。

### 4.10 合作、冲突、秘密与异常

- 当日明确发生的帮助、合作、争执、拒绝、回避和修复行为；
- 角色主动提及的秘密、传言和异常；
- 事件发生时间、参与者、地点和原文；
- 系统故障、路径失败、对话中断等技术异常单独列出。

“秘密”和“传言”只代表角色说过这些内容，不保证其在世界设定中为真。

### 4.11 赛事与公共事件

- 赛事或公共事件的开始、阶段、参与者和结果；
- 奖励、排名和角色公开发言；
- 事件结束后居民恢复了哪些日常活动；
- 后续出现的相关对话和活动记录。

本节只记录前后发生的事实，不自动声称赛事导致了后续变化。

### 4.12 数据说明与局限

- 哪些服务运行正常，哪些时段有中断；
- 哪些事件缺少开始、结束、地点或参与者；
- 本地 Gemma 12B 只用于对话与压缩摘要，不作为事实来源；
- 摘要的原始证据范围；
- 这是模拟社会记录，不能直接外推真实人群；
- AI 图片为虚构成年角色形象。

### 4.13 报告内附录

主报告末尾直接附：

- 居民日表；
- 全量关系边表和关系事件表；
- 地点访问与机构使用表；
- 劳动、交易、消费与服务表；
- 对话和消息索引；
- 公共事件表；
- 原始证据索引；
- 数据字段说明。

## 5. 描述性统计口径

系统只计算可以直接从记录得到的描述性数据：

- 活动开始数、完成数和类别数；
- 移动、抵达、离开和停留时长；
- 对话数、消息数、参与者和发起者；
- 地点访问数、独立访客数和同地出现次数；
- 关系事件数及明确写入的关系值变化；
- 工作、交易、消费和服务事件数；
- 议题词出现次数、说话人和时间顺序；
- 观察者介入次数；
- 期初、期末和差值。

不自动计算或解释中心性、阶层、派系、空间隔离、情感倾向、因果效应和心理状态。用户日后可利用 CSV/JSON 自行研究这些问题。

## 6. 摘要规则

- 摘要只压缩原始事实，不增加原因、动机和后果。
- 每个摘要段落携带覆盖的证据编号范围。
- 可使用本地 Gemma 12B 生成初稿，但必须经过规则检查：专有名词、数字、时间、人物和地点必须来自证据。
- 模型失败时使用确定性模板生成报告，不影响完整记录与导出。
- 原始文本永远保留；用户可以从摘要展开到原文。

## 7. 导出格式

观察台提供：

1. **预览全景观察档案**：在站点内按章节阅读，点击证据查看原始活动或对话。
2. **导出完整档案包**：下载 ZIP，包含：
   - `灯塔镇全景观察日报-YYYY-MM-DD-vN.md`；
   - `居民日表.csv`；
   - `关系与关系事件.csv`；
   - `地点访问.csv`；
   - `劳动交易与服务.csv`；
   - `对话与消息.csv`；
   - `公共事件.csv`；
   - `原始证据.json`；
   - `数据说明与局限.md`；
   - `manifest.json`，记录版本、文件哈希和生成环境。

主 Markdown 已包含全部核心内容和表格，附件用于用户日后自行统计与写论文。

## 8. 生成流程

1. 用户选择日期。
2. 后端按上海时区确定数据范围。
3. 读取并校验原始观察事件、对话、居民、关系、地点和公共事件。
4. 纯函数生成时间线、分类表和描述性计数。
5. 本地模型只压缩冗长对话和重复活动；规则校验摘要没有新增事实。
6. 生成报告正文、内嵌附录和证据索引。
7. 保存带版本的档案，提供站内预览。
8. 导出 Markdown、CSV、JSON 和 ZIP。

## 9. 错误处理与完整度

- 数据窗口不完整：报告顶部显示缺失时段和完整度警告。
- 模型超时：改用确定性模板，完整事实仍可导出。
- 重复事件：按幂等键去重，并记录去重数量。
- 缺少地点：保留坐标并标记“未命名地点”。
- 缺少结束事件：显示“未记录结束”，不伪造时间。
- 下载失败：保留已经生成的档案，可重新下载而不重复生成。
- 服务重启：新事件继续追加，不删除旧证据。
- 所有技术异常进入单独的运行记录，不混入角色行为解释。

## 10. UI 设计

观察台的“导出日报”升级为“全景观察档案”。点击后打开档案面板：

- 日期选择；
- 临时/已封存状态；
- 数据完整度、事件数、消息数、对话数和版本；
- “生成档案”“预览”“导出完整档案包”；
- 报告目录和分节阅读；
- 证据编号可展开查看原始记录；
- 角色设定、当日事实、技术异常使用不同标签；
- 长报告分节渲染，避免拖慢地图和居民模拟。

## 11. 测试策略

### 单元测试

- 上海时区自然日边界；
- 事件幂等和证据编号稳定性；
- 时间线排序和分类；
- 居民、关系、地点、机构、交易和对话表；
- 未结束停留、缺失地点和服务中断；
- 摘要不能包含证据中不存在的人物、地点、数字或事件；
- Markdown 表格、CSV 转义、JSON 清单和文件哈希。

### 集成测试

- 一组活动、移动、对话、机构服务和交易形成完整档案；
- 观察者介入被正确单列；
- 模型不可用时仍生成完整事实档案；
- 同日重新生成产生新版本，旧版本不变；
- 封存档案不受后续事件影响。

### 浏览器验收

- 能选择日期、生成、预览并导出档案包；
- 主报告包含全部 13 个章节和内嵌附录；
- 证据链接能定位到原始记录；
- 地图和居民运行不因报告生成而中断；
- 浏览器无关键错误；
- 下载的 Markdown、CSV 和 JSON 可以重新解析。

## 12. 验收标准

1. 任意有数据的自然日都能生成独立可读的全景观察档案。
2. 主报告完整记录全镇时间线、人物发展、关系、经济、空间、机构、对话、文化、异常和公共事件。
3. 每条具体事实能追溯到有效证据编号；没有记录的内容不会被补写。
4. 报告只做事实整理和描述性计数，不生成研究结论、动机解释或因果判断。
5. 可导出 Markdown、CSV、JSON 和带清单的 ZIP 档案包。
6. 模型失败不会丢失事实档案，历史封存版本不可变。
7. 全量测试、构建、资产校验、站点健康检查和浏览器实测通过后才能提交实现。

## 13. 非目标

- 不替用户写论文结论、理论框架或研究命题。
- 不自动判断社会中心、阶层、派系和因果关系。
- 不推测居民心理、真实动机或未说出的感情。
- 不伪造价格、收入、停留时间、关系变化或缺失事件。
- 不自动生成参考文献。
- 不把模拟居民的记录外推到真实社会。
- 首版不做多个小镇之间的比较研究。
