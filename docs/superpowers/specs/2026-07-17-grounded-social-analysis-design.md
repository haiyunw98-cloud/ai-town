# 灯塔镇有证据的社会分析设计

## 目标

让“社会观察日志”真正提供可审计的社会分析，而不是把事实流水账换一种说法。任何分析都必须能追溯到当天记录，并明确区分事实、模式、假设和未知项。

现场验证显示本地 `gemma4:12b` 能成功生成内容，但在居民模型请求繁忙时一次调用约需一分钟；现有提示又要求“只能整理明确事实”，导致输出倾向逐句复述。因此需要同时改进分析结构、规则回退和用户可见状态。

## 已选择方案

采用“规则计算证据指标 + 本地 Gemma 结构化分析 + 规则分析回退”。

不采用自由散文分析，因为难以审计且容易推断人物心理；不采用纯规则指标，因为用户需要自然语言解释与研究线索。

## 数据边界

输入仍来自同一份上海日期快照，包含：

- 当日生活事件与当前居民状态；
- 当日居民消息和观察者介入；
- 对话参与者、消息数和可引用短句；
- 机构与地点使用；
- 公共事件、活动和历史记录；
- 数据覆盖范围与缺失项。

设定资料只能用于解释字段含义，不能冒充当日发生的事实。没有跨日基线时不得写“上升、下降、持续恶化”等趋势；只能描述当日结构或提出需要后续比较的指标。

改造前由旧提示诱发的“异变、灯火装置、河道线索、花木线索、机关谜团”等内容标记为旧实验条件，不进入当前社会结构分析，也不得成为观察日志标题或主要发现。原始消息仍完整保留在事实导出中，方法说明同时注明该过滤规则，避免研究者把产品旧设定误当成居民自然形成的议题。

## 证据与规则分析层

在调用模型前生成稳定的 `ObservationEvidence`：

- `evidenceId`：报告内唯一且稳定的编号。
- `category`：互动网络、关系迹象、劳动商业、机构使用、公共生活、观察者介入或数据覆盖。
- `statement`：由确定性代码生成的事实或统计模式。
- `sourceKeys`：消息、生活事件、会话或日志的原始键。
- `confidence`：仅反映数据覆盖，取高、中、低。
- `limitations`：样本量、缺失时间、身份映射或无法判断的边界。

规则层至少计算：

1. 对话网络规模、互动次数、孤立居民和互动集中度。
2. 活动类别分布与劳动、消费、照护、社交覆盖。
3. 机构使用次数和使用是否集中在少数地点。
4. 合作、友情、亲密关系、商业与分歧的明确迹象；没有记录时写无记录。
5. 观察者介入次数，以及介入前后可见活动差异；样本不足时禁止暗示影响。
6. 当日公共活动与普通生活的占比。

这些指标同时生成一组规则分析发现。即使模型失败，报告仍包含“模式 + 证据编号 + 替代解释 + 限制”，不能退化为纯流水账。

## Gemma 分析协议

社会观察 action 仍只允许本地 Ollama，并固定使用 `gemma4:12b`。模型接收有界、不可执行的 JSON 证据包，不接收系统密钥或未过滤的运行日志。

模型必须返回可验证的结构化结果：

```text
findings: 3–5 条
  claim: 审慎的模式判断
  evidenceIds: 至少一个有效证据编号
  confidence: 高 / 中 / 低
  alternativeExplanation: 至少一个其他可能解释
limitations: 2–4 条
followUps: 2–4 个后续应继续记录的问题
```

允许的分析包括：互动是否集中、哪些机构承担较多公共功能、劳动和照护是否由少数居民承担、关系网络中出现哪些明确合作迹象、观察者介入附近发生了什么可见变化。

禁止心理诊断、道德评价、人物动机定论、凭一次记录建立因果关系、编造未出现的关系，以及把观察写成论文结论。

输出目标为 600–1000 个中文字符。相比原有长篇复述，减少生成量并把篇幅用于分析。

## 验证与降级

模型结果必须通过以下验证：

- 每条发现至少引用一个存在的 `evidenceId`。
- 置信度只能取允许值。
- 每条发现包含替代解释。
- 不得新增人物、地点、机构或事件。
- 不得包含 Markdown/HTML 注入、心理诊断或确定性因果措辞。

验证失败、Ollama 离线、provider 不是 Ollama 或响应为空时，使用规则分析发现。报告明确标注来源：

- `本地 Gemma 辅助分析`
- `规则分析（本地模型未完成）`

降级原因只使用脱敏枚举，如 `模型不可用`、`输出无效`、`配置非本地`，不写请求正文、模型正文、主机凭据或堆栈。

## 报告呈现

保留现有十个固定章节和事实流水账的独立性。“本地模型辅助的谨慎观察”章节改为逐条展示：

- 分析发现；
- 证据编号；
- 置信度；
- 其他可能解释。

“后续值得持续记录的线索”使用结构化 `followUps`；“方法与边界说明”列出模型来源、降级状态、覆盖时段和无法得出的结论。

事实流水账不吸收这些分析内容，仍只记录发生了什么。

## 用户交互与性能

生成按钮继续使用跨标签持久任务锁。状态按阶段显示：

1. `正在统计当日事实`
2. `正在等待本地 Gemma（可能需要约一分钟）`
3. `正在整理分析结果`

不自动暂停小镇，不卸载 Ollama，也不调用 DeepSeek 或其他付费模型。对话短轮次改造完成后，本地模型队列占用预计下降，但 UI 不承诺固定完成秒数。

## 部署与隐私边界

- 本地自托管 Convex 时，证据包和模型请求均可留在本机。
- 使用云 Convex deployment 时，证据包会先提交到该 deployment，再由 action 请求配置的 Ollama；研究资料需要据此选择部署方式。
- 浏览器下载仍在本地完成，报告正文不写入新的云端表。

## 测试与验收

1. 规则证据编号稳定、可追溯，且不会修改输入快照。
2. 固定样本产生网络、机构、劳动/活动和观察者覆盖指标。
3. 无跨日数据时，输出不得声称跨日趋势。
4. Prompt 明确要求分析、证据引用、置信度、替代解释和限制，不再要求连续事实复述。
5. 结构化模型响应必须逐字段验证；未知证据编号触发规则回退。
6. Provider 非 Ollama 时不调用 completion；模型固定为 `gemma4:12b`。
7. 模型失败后的报告仍至少包含三条规则分析发现，而不是空白或事实重排。
8. 报告明确显示分析来源和脱敏降级原因。
9. 同一点击使用同一快照、日期和证据包；切换标签不重复生成。
10. 生产构建、客户端边界、世界资源和独立站点健康检查通过。
11. 含旧谜团样本的输入不会生成“小镇异变”或灯火、河道、花木线索分析；报告方法说明会披露旧实验条件过滤，原始事实导出不受影响。

## 非目标

- 本阶段不自动生成论文结论、人格判定或因果推断。
- 本阶段不引入跨日数据库聚合；跨日趋势留给后续研究数据仓库。
- 本阶段不调用云端大模型，也不改变居民模型的固定本地优先策略。
- 本阶段不实现完整经济系统或新的活动地图。
